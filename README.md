# Proyecto Sistema de Gestión Genérico para Torneos

Descripción:
El Sistema de Gestión Genérico para Torneos es un modelo de base de datos relacional diseñado para administrar cualquier tipo de competición deportiva, permitiendo gestionar equipos o participantes individuales, registrar el historial de jugadores y entrenadores en los equipos, organizar torneos con múltiples ediciones, y almacenar la información de los encuentros (fecha, participantes, resultados y sede), todo dentro de un esquema flexible y neutral que puede adaptarse a distintas disciplinas deportivas.

Motivación:
Este proyecto surge de la necesidad de organizar eficientemente la información generada en torneos deportivos (participantes, resultados, historial), permitiendo aplicar conceptos fundamentales de bases de datos en un caso práctico y real, con la ventaja de ser un modelo flexible que se adapta a diferentes disciplinas y que puede servir como base para futuros desarrollos de aplicaciones de gestión deportiva.

*¿Que cambios y forma normal se utilizo al normalizar los diagramas de bases de datos?*
En el diagrama E-R se realizaron cambios enfocados en eliminar redundancias y mejorar la estructura de las relaciones. Las relaciones muchos a muchos, como entre equipos y jugadores, equipos y entrenadores, y equipos y partidos, fueron transformadas para cumplir con las formas normales. Además, se separó correctamente la entidad torneo de edición, permitiendo una mejor organización de los datos a lo largo del tiempo. También se reorganizó la entidad partido, dejando únicamente atributos propios como fecha y ID, mientras que la participación de equipos y sus puntuaciones se eliminaron. Finalmente, se definieron mejor algunos atributos como el capitán, ubicándolo dentro de la relación correspondiente, logrando así un modelo más claro, sin redundancias y en tercera forma normal.
En el diagrama UML se realizaron varios cambios importantes para mejorar la estructura y eliminar redundancias. En la entidad Partido se eliminaron los atributos id_equipo_local, id_equipo_visitante, goles_local y goles_visitante, ya que generaban dependencias incorrectas, dejando únicamente los datos propios del partido como fecha, id_edicion e id_estadio. También se corrigió el uso de claves, cambiando id_estadio de clave primaria a clave foránea. En la entidad Entrenador se eliminó el atributo codigo_equipo, evitando una relación directa incorrecta y permitiendo una mejor normalización. Asimismo, se eliminaron las tablas intermedias Integran y Entrena que contenían identificadores innecesarios (id_integran e id_entrena). Además, se renombró y estructuró correctamente la entidad Edición (antes Ediccion_de_torneo), separándola claramente de Torneo. Finalmente, se agregaron tipos de datos a todos los atributos, logrando un modelo más consistente, sin redundancias y alineado con la Tercera Forma Normal.
